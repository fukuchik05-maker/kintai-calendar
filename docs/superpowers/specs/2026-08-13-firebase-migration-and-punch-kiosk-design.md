# Firebase移行 + バーコード打刻キオスクページ 設計書

- 日付: 2026-08-13
- ステータス: 承認待ち

## 背景・目的

これまでLocalStorage単体で動いていた勤怠管理カレンダーを、以下2点を満たすためにFirebase(Firestore)ベースに移行する。

1. ブラウザのデータ消失リスクをなくす(クラウドに保存)
2. 別のPC・自宅からもアクセスできるようにする

加えて、共有PCの前にいなくても実際の出退勤時刻を記録できるよう、**バーコードリーダーで職員コードを読み取るだけの専用打刻ページ**を新設する。これにより「基本の勤怠は自動入力、時間外だけ実際の時刻で打刻」という運用が、共有PC以外の場所(入口に置いた端末等)からも可能になる。

## 全体方針・決定事項

- **DB**: Firebase Firestore(プロジェクト名: `kintai-calendar-2026`、Standardエディション、本番環境モード、東京リージョン `asia-northeast1`、Google アナリティクスは無効)
- **ホスティング**: GitHub Pages(静的ファイルのみ。サーバーサイドの処理は一切持たない)
- **アクセス制限**: 今回は設けない(URLを知っている人だけが使う前提)。将来的に簡易パスコードやFirebase認証を追加する余地は残す
- **既存の画面・機能(カレンダー/一覧表示/月報/CSV出力/バックアップ等)の見た目・操作感は一切変更しない**。変わるのは「データの保存先」だけ
- 新規に**打刻専用ページ(`kiosk.html`)**を追加する

## データモデル(Firestore)

現在のLocalStorage内の1つのJSONオブジェクト(`{ members, records, dayNotes }`)を、Firestoreのコレクション/ドキュメントに分割する。

```
members (コレクション)
  ドキュメントID = メンバーID (例: "m1")
  { name, grantedLeaveDays, employeeCode }   // employeeCodeを新規追加(バーコードの値)

records (コレクション)
  ドキュメントID = "{日付}_{メンバーID}" (例: "2026-08-13_m1")
  { date, memberId, status, clockIn, clockOut, breakMin, hourlyLeaveHours, note }

dayNotes (コレクション)
  ドキュメントID = 日付 (例: "2026-08-13")
  { date, text }
```

日付×メンバーやメンバー単位でドキュメントを分けることで、打刻ページ(1レコードだけ書き込み)とカレンダー画面(色々なレコードを編集)が同時に操作しても、互いの変更を上書きしてしまう心配がない。

## storage.js の変更方針

- 既存の `Storage.loadData()` / `Storage.saveData()` という2つの窓口はそのまま残すが、内部実装をLocalStorageからFirestore呼び出しに差し替える
- 上記2関数は非同期(Promiseを返す)に変更する。呼び出し元(`initState`, `persistAndRerender` 等)もそれに合わせて `async/await` 化する
- `app.js` / `modals.js` / `gantt.js` / `summary.js` など、画面側のロジックは「`App.state.data` というJSオブジェクトを読み書きする」という今までのやり方を維持する(Firestoreへの個別書き込みは `saveData` 内で吸収する)
- JSONバックアップ書き出し/読み込み機能は今まで通り動作させる(Firestoreの中身をエクスポート/インポートする形に変える)

## 打刻ページ(kiosk.html)

- 既存アプリとは別のHTMLファイルとして新設し、同じFirestoreデータを参照する
- 画面には職員コード入力用のテキストボックスが1つだけあり、常にフォーカスが当たっている
- USBバーコードリーダーは「キーボード入力の代わり」として動作するため、専用SDKは不要。バーコードの値が入力されEnterが押されたタイミングで処理する
- 職員コードから該当メンバーを特定できない場合はエラー表示のみ行い、何も記録しない
- 打刻ロジック(時刻ベース、`Calc.STANDARD_START_MIN` / `STANDARD_END_MIN` を流用):
  - 現在時刻が8:30より前 → その日のレコードの `clockIn` を現在時刻で更新(status: 出勤)
  - 現在時刻が17:30より後 → `clockOut` を現在時刻で更新
  - 8:30〜17:30の間 → `clockOut` を現在時刻で更新(早退として扱う)
  - その日のレコードがまだ存在しない場合は、平日一括入力と同じ初期値(status: 出勤、breakMin: 60等)で新規作成してから該当フィールドを上書きする
- 記録後、画面に「〇〇さん 出勤(または退勤)を 14:32 で記録しました」のようなフィードバックを数秒間表示し、次のスキャンに備えて自動的に入力欄をクリア・再フォーカスする

## メンバー設定の変更

- メンバー設定モーダルに「職員コード」の入力欄を追加する(バーコードの値を登録する用途)

## Firestore セキュリティルール

- 今回はアクセス制限を設けない方針のため、`members` / `records` / `dayNotes` の3コレクションについて「誰でも読み書き可能」とするルールを設定する
- 将来的にパスコードや認証を追加したくなった場合に備え、ルールファイルは分かりやすくコメントを残す

## デプロイ手順(概要)

1. このリポジトリをGitHubの新規リポジトリにpushする
2. GitHub Pagesを有効化(mainブランチ、ルートディレクトリを公開)
3. Firebase Consoleでセキュリティルールを設定
4. 公開されたURLで動作確認

## テスト方針

- Firestore連携部分はNode.js単体テストの対象外とする(実際のFirestoreプロジェクトへの接続が必要なため)。代わりに、実際のFirebaseプロジェクトに対してブラウザ操作で動作確認する
- 既存の計算ロジック(calc.js / holidays.js)は変更しないため、既存の単体テストはそのまま維持・実行する
- 打刻ページの時刻判定ロジック(8:30/17:30境界)は純粋関数として切り出し、Node単体テストを追加する

## スコープ外(今回はやらないこと)

- アクセス制限(パスコード・ログイン)の実装
- オフライン対応(通信できない環境での利用)
- 打刻ページ以外からの職員コード入力(手入力フォーム等)
- Firestoreへの移行に伴う、既存LocalStorageデータの自動移行スクリプト(必要になれば別途対応)
